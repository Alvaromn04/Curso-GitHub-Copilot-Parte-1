# Execution Process

Execution is where planned work is delivered iteratively.

## Objectives

- Ship validated increments continuously.
- Keep risks, blockers, and dependencies visible.
- Maintain quality and predictability throughout delivery.

## Core Activities

1. Track flow using the team board (Backlog → Ready → In Progress → In Review → QA → Done).
2. Run daily standups and weekly delivery syncs.
3. Use pull requests with automated checks and reviewer approval.

## Exit Criteria

- Planned scope for the release is complete or explicitly re-baselined.
- Outstanding blockers are resolved or formally accepted.
- QA sign-off is complete for release candidate scope.
